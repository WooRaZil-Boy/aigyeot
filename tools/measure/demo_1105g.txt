## 공조 전원 조사
- 관찰 도구: `GET /vehicle/hvac`의 power_on, `dumpsys car_service --hal`의 HVAC_POWER_ON lastEvent, logcat `sdv_vhal_rust … power on callback`.
- VC 웹 페이지(`GET /`)의 JS에서 찾은 쓰기 경로: `PUT /vehicle/hvac?power=0|1`(전원 토글의 필드 이름이 `power`), 같은 호출에 `driver_temp=`·`auto=`·`ac=`·`sync=`·`recirc=`·`front_defroster=`·`rear_defroster=`·`fan_speed`를 함께 보낼 수 있다. `GET /vehicle/hvac`이 상태를 읽는다(power_on 포함).
- 재현 시도(모두 power_on이 true로 남음, 콜백은 ON만 나옴):
  1. 콜드 부팅 직후 첫 VC 활성화(외부 세션 신호): 22:09:43 `new: ON`.
  2. 세션 신호 끊고 5초 뒤 다시 켬: 전원 true 유지.
  3. 세션 신호 끊고 60초 뒤 다시 켬(22:23:09): `new: ON`.
  4. 앱이 장면 B를 시작하며 세션을 처음 켬(외부 세션 신호 없음, 22:24:37): `new: ON`.
- 강제로 `PUT /vehicle/hvac?power=0`을 보내면 VHAL이 OFF(22:23:37 콜백 `new: OFF`)가 되고 차 화면 공조가 "꺼짐"으로 바뀐다(car_ui_공조꺼짐_VC_power0.png). `PUT /vehicle/hvac?power=1`을 보내면 2초 안에 ON으로 돌아가고 화면이 복구된다(22:23:40 `new: ON`, car_ui_공조켬_VC_power1.png는 장면 B 뒤 주행 상태 화면에서 찍음: 하단 공조가 켬).
  - 응답 본문은 전체 `/vehicle/state`(약 20KB)라 스크립트는 본문을 버린다.
- 시도하지 않은 방법: `adb shell cmd car_service set-property-value`(user 빌드에서 `cmd car_service help`가 SecurityException 'requires non-user build', volume_perm_1105d.txt 45줄), `adb root`(user 빌드). VC `power=1`로 충분해서 쓰지 않았다.
- 결론: 이번 부팅에서는 OFF가 저절로 생기지 않았다. 1105c의 OFF 원인은 확인하지 못했다(미확인). 대책은 기준값에 `power=1`을 넣고 되돌린 뒤 `power_on`을 읽어 확인하는 것이다(`set_baseline`, 실패하면 멈춤).

## 수정 뒤 확인 2(에뮬레이터 없이, 가짜 `a()`로 확인)
- vc.sh `app_front`(62~67줄): monkey 대체를 지웠다(Android 14 Monkey가 `--user`를 거절). `am start`의 종료 코드가 0이 아니거나 출력에 `Error`·`Exception`이 있으면 출력 앞부분과 함께 멈춘다. 성공이면 아무것도 찍지 않는다. `bash -n vc.sh` 통과.
- 확인: vc.sh를 source한 뒤 `a()`를 가짜 함수로 바꿔 세 경우를 돌렸다. 실제 adb·에뮬레이터는 쓰지 않았다.
  - (가) "Starting: Intent { cmp=kr.aigyeot.app/.MainActivity }", rc 0 → 통과(출력 없음, rc 0)
  - (나) "adb: device 'emulator-5560' not found", rc 1 → "실패: 앱을 띄우지 못했다(종료 코드 1): adb: device …" 후 프로세스 rc=1
  - (다) "Error: Activity class {…} does not exist.", rc 0 → "실패: 앱을 띄우지 못했다: Error: Activity class …" 후 프로세스 rc=1
- 실제 기기에서의 `app_front` 동작은 이번에 다시 돌리지 않았다(1회차 수정 확인에서 reset·prepare가 통과한 것은 monkey 제거 전 코드).
