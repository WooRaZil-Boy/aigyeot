## 3. 보강(tools/demo/vc.sh)
- ui_wait(새 함수): 덤프에서 글자를 찾을 때까지 UI_WAIT_S초(기본 10) 동안 1.5초마다 다시 찾는다. 그 사이의 덤프 실패도 다시 하고, 마지막 한 번은 덤프 실패 메시지를 그대로 보인다. ui_dump의 '앞 덤프 파일 먼저 지움'(옛 좌표 방지)은 그대로
- ambient_switch: 차량 설정을 열고 1초 뒤 ui_wait로 '라이트'를 약 5초 찾고, 없으면 차량 설정을 다시 연다(최대 세 번). 세 번 다 없으면 같은 뜻의 메시지('라이트' 항목을 찾지 못했다, 차량 설정을 세 번 열어 봄)로 멈춘다
- '무드 조명' 스크롤 고리: 덤프가 한 번 실패해도 원래 멈추지 않았다($(...) 안의 실패라 빈 결과로 다시 스크롤). 중간 실패 메시지만 숨겼다
- 다시 열기 확인(일부러 가림): 차량 설정을 연 1.3초 뒤 내비 앱을 앞으로 띄워 가리자, 약 10초 뒤 차량 설정을 다시 열고(logcat START 두 번) 무드 조명 켜기까지 끝남(21초)

## 7. 보강(tools/demo/vc.sh 100~141줄)
- ambient_switch: 한 번 시도(ambient_try)가 어디서 막히든 차량 설정 열기부터 다시 한다(최대 세 번). 세 번 다 막히면 '무드 조명 …을 누르지 못했다(차량 설정을 세 번 열어 봄)'으로 멈춘다
- ambient_try: 차량 설정 열기 → '라이트' 약 5초 기다림 → 탭 → 스크롤마다 덤프에 차량 설정 왼쪽 메뉴 '라이트'가 남아 있는지 본다(vc_gone). 사라졌으면 더 스크롤하지 않고 바로 다시 시도.
  '무드 조명' 다음의 칸을 누른 뒤에도 한 번 더 덤프해 차량 설정이 남아 있는지 본다(누르는 순간 닫혔으면 다른 화면을 누른 것이라 다시). 덤프가 실패한 빈 결과는 '사라짐'으로 보지 않는다
- '무드 조명' 글자가 보일 때까지 기다리는 방식은 쓰지 않았다: '라이트'를 누르면 맨 위가 보여 '무드 조명'은 스크롤 전에는 화면에 없다. 이미 켜기여도 다시 누른다(같은 칸을 다시 눌러도 그대로)
- 호출하는 곳: prepare.sh(ambient_on), stop.sh(ambient_off). reset.sh는 스위치를 건드리지 않는다
