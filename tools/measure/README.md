## 에뮬레이터 실측

Pleos 공식 에뮬레이터에서 잰 값입니다. 장면은 마이크 자리에 울음 녹음을 섞은 것이라 실제 마이크로 들은 값이 아닙니다. 성능은 debug 빌드로 쟀습니다. 11-10에 3D 화면이 들어갔으므로 성능은 3D가 들어간 최신 측정(11-12)을 먼저 적고 그 전 측정(11-08)을 함께 둡니다. 두 측정은 AVD(11-08 `PleosProbe`, 11-12 `PleosConnect`)·장면 구성·표본 간격이 달라, 둘의 차이를 3D 화면 영향으로 따로 판정하지 않습니다.

## 맥 오프라인 평가

맥에서 파이썬으로 돌린 평가입니다(`mediapipe` 0.10.14, 환경은 [tools/cry-retrain](../cry-retrain/)). 재현율·오경보 숫자는 **교차검증(학습에 안 쓴 접기로 잼)** 값입니다. 같은 구조의 판별층을 접기마다 새로 학습해, 그 판별층이 학습에 쓰지 않은 접기에서 점수를 냈습니다(`rt_train.py`). 앱에 들어가는 `cry_head24_rt.json`은 같은 데이터 전체로 학습한 것입니다. 그래서 이 판별층에 진짜 학습 밖 시험은 AxonData(독립 울음 18개)와 아래 장면 시험(첫 경보·R1·R3)입니다. 장면 시험은 내보낸 판별층을 그대로 씁니다. 스크립트와 결과 파일은 [tools/cry-retrain](../cry-retrain/)에 있습니다.

| 항목 | 결과 | 조건 |
| --- | --- | --- |
| 울음 경보 재현율(교차검증) | 378/457(0.83) | 휴대폰으로 녹음한 아기 울음(Donate-a-Cry) 457개, 울음 대 차 소음 비 10 dB, 기준 0.7. 이전 판별층은 0.64(같은 기준 0.7) / 0.70(이전 판별층 자신의 기준 0.5) |
| 오경보(교차검증) | 말소리 0/497, 음악 0/144, 노래(CSD) 7/107, ESC 다른 소리 15/1960 | 같은 조건. 말소리 497개에는 판정 구간이 하나뿐인 짧은 클립도 들어 있고, 이런 클립은 '3초 구간 두 번 연속' 경보 규칙(`app/src/main/assets/cry_head24_rt.json`의 `alarm`)상 경보를 낼 수 없습니다(그 수는 공개 기록이 없어 적지 않음) |
| 첫 경보 지연(장면 시험) | 중앙값 2.4초, 360장면 중 357장면에서 경보 | `rt_stop.py`. 재생은 울음 시작 6초 뒤에 켜지므로 첫 경보 357개 중 353개가 울음 시작 6초 안, 곧 재생이 켜지기 전에 났습니다. 재생 중 소음에 대한 강건성을 잰 값이 아닙니다 |
| 달래기 성공·실패 판정(R3) | 359/360 | 56초에 재생을 멈추고 8초 듣고, 재생을 끈 채 30초 더 확인 |
| 재생을 끄지 않고 t0+30~60초로 판정할 때(R1, 비교용), 노래 장면 | 실제로 그친 72번 중 54번 맞힘, 계속 운 72번은 72번 모두 맞힘 | 18번은 노래를 울음으로 착각해 '아직 운다'로 잘못 봤습니다 |

조건과 한계는 다음과 같습니다.
- R1·R3의 360번 = 학습에 쓰지 않은 가정 울음 녹음 18개(AxonData) × 울음 대 차 소음 비 2가지(10, 0 dB) × 정답 2가지(그침·계속) × 재생 조건 5가지(없음, 백색소음, 브라운 잡음, 노래 두 크기)입니다. 조건마다 소음을 새로 뽑았습니다.
- 첫 경보 지연(`rt_stop`)의 360장면은 구성이 다릅니다. 같은 울음 18개 × 소음 비 2가지 × 재생 조건 10가지(없음, 백색소음·브라운 잡음·노래 각 두 크기, 20초 틀고 4초 멈추는 듣기 틈 세 가지)이고, 그침·계속으로 나누지 않고 울음 파일 전체를 씁니다.
- 장면의 경계가 분명합니다. '그침' 장면은 첫 재생 5~25초 뒤(울음 파일이 그보다 짧으면 그 전)에 울음이 끝나고, '계속' 장면은 첫 재생(t0) 76초 뒤까지 이어집니다. 확인 중에 다시 우는 경우와 판정 시점 근처에서 그치는 경우는 시험하지 않았습니다.
- 장면 시험(R1·R3·`rt_stop`)의 차 소음은 학습에 쓴 것과 같은 DEMAND TCAR 300초 녹음에서 뽑았습니다. 같은 60초 구간 다섯 개 중 하나를 고르므로 소음은 학습 밖이 아닙니다.
- R1 시험에 쓴 노래는 판별층이 '울음 아님'으로 배운 노래와 같은 곡입니다.
- 평가는 `mediapipe` 0.10.14로 돌렸고 앱은 tasks-audio 0.10.32를 씁니다. 두 버전의 기기 확률은 위 에뮬레이터 표대로 같았습니다.

## 알려진 한계와 확인하지 못한 것

- **실제 효과:** 아기가 실제로 덜 우는지, 운전자가 덜 돌아보는지는 재지 않았습니다. 아기와 사람이 있어야 잴 수 있습니다. 앱의 성적은 '그 소리를 틀었을 때 그친 횟수'이고, 소리 덕분인지는 알 수 없습니다.
- **듣지 못한 시간의 리포트 표시:** 마이크 입력이 끊긴 동안(다른 앱이 마이크를 무음 처리하거나, 에뮬레이터 마이크에 소리가 들어오지 않을 때)은 판정을 멈추고 울음을 기록하지 않습니다. 주행 중 화면은 이때 '아직 듣지 못하고 있어요'를 보이지만, 주행 리포트는 듣지 못한 시간을 따로 표시하지 않아 주행 내내 듣지 못했어도 '울음 기록 없음'으로 보입니다.
- **설계값:** 56초·8초·30초·자동 시도 2회는 제품 설계값입니다. 임상 기준이 아닙니다.
- **감지 수치의 조건:** 휴대폰·가정 녹음에 차 소음을 섞어 맥에서 잰 값입니다. 차 안에서 녹음한 울음, 긴 녹음에서의 시간당 오경보, 형제 소리(웃음 등)는 따로 재지 않았습니다.
- **에뮬레이터 소리:** 에뮬레이터 소리는 맥 스피커로 나와 앞·뒤로 나뉘어 들리는지는 확인할 수 없습니다([mic_loopback_gleo_1103.txt](mic_loopback_gleo_1103.txt) 한계 1). 11-03 측정에서는 `-allow-host-audio`로 띄워도 재생 전후 입력 rms가 0.0~0.6으로 같아 맥 소리가 들어오지 않았습니다(맥의 마이크 권한은 따로 주지 않음, 같은 파일 한계 2). 맥 기본 입력을 가상 오디오 장치(BlackHole 2ch)로 바꾸고 울음 녹음을 그 장치로 내보내면 에뮬레이터 마이크가 받습니다. 이렇게 장면이 아닌 실제 세션에서 경보·달래기·그침을 거쳐 차·휴대폰 리포트 값이 서로 맞는 것을 확인했습니다([e2e_cry_drive_1111.txt](e2e_cry_drive_1111.txt)). 뒷좌석 재생 소리가 마이크로 되돌아오는지, 쉼터 질문에 목소리로 '응' 하는 경로는 여전히 미판정입니다. 장면은 '응'을 직접 넣습니다.
- **순정 음성 비서·통화와 함께 쓸 때:** 마이크 무음 처리와 오디오 포커스 겹침은 에뮬레이터에서 만들지 못해 미판정입니다.
- **실차 오디오 존:** 에뮬레이터의 뒷좌석 존(`bus100_audio_zone_1`) 기준입니다. 존 구성은 차마다 다를 수 있고 실차는 확인하지 않았습니다.
- **실내 온도:** 에뮬레이터 실내 온도는 19.1℃로 고정입니다. 공조를 낮추는 장면 B는 실내 27℃를 장면이 넣습니다.
- **x86_64(Windows·Linux) 에뮬레이터:** APK에 x86_64 라이브러리가 들어 있는 것까지만 확인했습니다. 실행은 미판정입니다(맥 Apple Silicon에서 x86_64 이미지를 띄우지 못함).
- **말로 묻기의 LLM 답:** 지금 코드의 시스템 지시(p7)로 맥에서 같은 질문 73개를 동시 3번·순차 2번 부른 지연은 중앙값 1,864ms, p90 2,456ms이고, 차가 기다리는 3초를 넘긴 것은 9/363건(2.5%, 그중 7건은 동시 묶음, 원인 미판정)입니다([llm_p7_1111.txt](llm_p7_1111.txt) 1절). 같은 조건에서 앞 지시(p6)는 중앙값 1,999ms, 3초 초과 2/363건(0.6%)이었습니다. 3초를 넘기면 차는 정해 둔 문장으로 답합니다. 앞 지시(p6)로 배포한 중계로 차 경로를 시험한 세 질문은 2.2~3.0초였고, p7로 다시 배포한 뒤에는 통과 여부만 봤습니다([relay_deploy_sonnet_1111.txt](relay_deploy_sonnet_1111.txt) 2·5절). 배포한 중계에서 3초를 넘기는 비율은 재지 않았습니다(미판정). 목소리로 물은 실제 사례의 단계별 지연은 한 번만 쟀습니다(llm_1110.txt 8절).
- **원격 푸시:** FCM·APNs 키를 넣지 않아 실제 도착은 미판정입니다.
- **에뮬레이터 안정성:** 맥 부하가 높을 때 에뮬레이터 CarService가 다시 뜨는 일이 있었습니다. 그때 앱 응답 없음(ANR)이 두 번 기록됐고(차 연결 콜백이 차량 서비스 호출에 막힘), 원인을 고쳤습니다. 고친 뒤 맥 부하가 1분 평균 136~157까지 오른 때 CarService가 7번 다시 뜬 동안 앱은 그대로 살아 있었고 ANR은 0이었습니다(한 번 관찰). 이때 무드 조명 스위치가 꺼짐으로 돌아갑니다. 장면 도중이면 차량 설정 → 라이트 → '무드 조명'에서 '켜기'를 누르고 앱으로 돌아옵니다. `tools/demo/prepare.sh`는 APK를 다시 설치해(`adb install -r`) 앱을 끝내므로 장면 사이에만 씁니다. 기록: [emulator_1110.txt](emulator_1110.txt), [featD_1110.txt](featD_1110.txt).
- **SDK 신청:** Vehicle Control·TTS·STT 사용 신청이 아직 '준비 중'이라 실차 배포는 신청이 열린 뒤에 할 수 있습니다. 에뮬레이터에서 동작한다고 앱 마켓 심사(상시 청취, 뒷좌석 자동 재생)를 통과한다는 뜻은 아닙니다.
- **학습 데이터:** 비상업 조건 데이터가 들어 있어 판별층은 공모전 시연용입니다. 상용 배포 전에 상용 가능한 데이터로 다시 학습합니다.
