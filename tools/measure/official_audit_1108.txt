 2) 이미 A가 있는데 FIRST로 B 추가 -> wpInfo [A, B]. A가 사라지지 않았고 B는 앞이 아니라 뒤(두 번째 칸)로 붙었다. 회차 B에서 먼 곳(E, 74km)을 FIRST, 가까운 곳(F)을 나중에 FIRST로 넣었는데 [E, F]로 나왔다. 거리순 정렬이 아니라 삽입순이다. 두 번째 추가의 waypointChanged도 index=FIRST로 온다(index 필드를 믿을 수 없다).
 3) 두 칸이 찬 상태에서 SECOND로 C, FIRST로 D -> 이벤트도 onError도 없고(20초 대기, 두 번 확인) wpInfo는 [A, B] 그대로. 조용히 무시된다.
 4) removeWaypoint(ALL) -> routeCancelled 뒤 waypointChanged(index=FIRST, cmdType=REMOVE), wpInfo n=0, 경로는 목적지만 남아 재개.
 5) 빈 상태에서 SECOND로 추가(wp2 H) -> waypointChanged index=FIRST, wpInfo [H]. 인덱스 인자는 무시되고 "다음 빈 칸에 붙이는 큐"로 동작한다.
판정: 덮어쓰기 아님, 끼워 넣기도 아님. 인덱스 인자와 무관하게 빈 칸에 뒤로 붙고, 두 칸이 차면 응답 없이 무시. (이 에뮬레이터 내비 앱 한정.)
앱 영향: 추가 뒤 onWaypointChanged(약 8~10초)와 getWaypointInfo 개수로 확인해야 하며, 두 칸이 찬 경우 onError가 없으므로 시간 초과를 실패로 다뤄야 한다. 휴게소 경유지를 바꾸려면 removeWaypoint 뒤 다시 추가.

판정:
 영역: SeatArea 한 객체 = [ROW_1_LEFT, ROW_1_RIGHT, ROW_2_LEFT, ROW_2_CENTER, ROW_2_RIGHT](5개 값이 묶인 실내 전체 한 영역). 운전석(ROW_1_LEFT)이 포함된다.
 밝기 범위: AreaBounds(minValue=0, maxValue=100). 접근 READ_WRITE. 스위치 지원 값 [AUTOMATIC, ON, OFF], 색 접근 READ_WRITE.
 읽기: 스위치 OFF, 색 0xffffff(알파 없이 24비트), 밝기 70.
 주행 모드 자동 색: 이 에뮬레이터는 지원하지 않는다. checkAmbientColorAutoByDriveModeEnabledCapabilities -> ERROR_NOT_SUPPORTED_PROPERTY, getAmbientColorAutoByDriveModeEnabled -> IllegalArgumentException "property ID is not in carPropertyConfig list ... 0x21200787". 기본값은 읽을 수 없음(미판정). 앱은 예외를 '꺼진 것으로 보지 않고 미지원'으로 다뤄야 한다.
 밝기 set: 정차 6/6, 주행(D, 60km/h) 6/6 (set 콜백 값 = 0.5초 뒤 되읽은 값). 색은 11-02에 6/6(tools/sim/babycare_Drive.txt).
 원래 값 복구: 각 회차 끝에 밝기 70으로 되돌렸고 주행 회차 시작 읽기가 70이어서 확인됨. 스위치·색은 set하지 않았다.
 권한: 프로브에 CAR_LIGHTS와 CONTROL_CAR_LIGHTS를 모두 선언한 상태에서 잼. 'CAR_LIGHTS만' 선언했을 때의 동작은 이번에도 미측정.
