아이곁 중계·폰 성능 (2026-11-03)

목적: 중계(relay/), 안드로이드 폰(phone/android/), iOS 폰(phone/ios/)의 자원 사용과 효율을 본다. 이 셋에는 공식 성능 예산이 없어 새 기준 숫자를 만들지 않고, 잰 값과 '문제 있음/없음'의 근거만 적는다.
방법: 중계·폰 두 앱 모두 소스 읽기. 중계는 추가로 npm test와 wrangler dev --port 8787(로컬)에 요청을 보내 처리 시간을 쟀다(쟀던 스크립트는 저장소 밖 임시 폴더). iOS는 Rfc3339.parse를 그대로 옮긴 작은 Swift 프로그램(swiftc -O, 맥 호스트)으로 한 번 부르는 시간을 쟀다.
읽는 법: [문제]는 파일:줄, 근거, 영향, 최소 수정안 순이다. 등급은 높음/중간/낮음(자원 낭비 크기 기준)이며 계약 위반 여부와는 별개다. '문제 없음'은 읽은 범위에서 못 찾았다는 뜻이다.
한계: 중계 시간은 로컬 workerd 한 프로세스, 요청 한 줄씩(동시 부하 없음)이다. SQLite 읽은 행 수·청구는 로컬에서 보이지 않아 코드로 추정했다. 안드로이드는 에뮬레이터·실기기에서 돌리지 않았다(배터리·메모리 미판정). iOS 시뮬레이터에서 앱 메모리는 재지 않았다(미판정: 이미 다른 앱이 켜진 시뮬레이터가 있고 앱 빌드·설치 시간이 30분 안에 맞지 않는다고 봤다). iOS 시간은 맥 호스트 값이라 아이폰과 다르다.

== 중계: 문제 없음으로 본 것 ==
- 알람: CarRoom은 가장 이른 만료 시각 하나만 설정한다(메시지·노래 7일, 푸시 next_at, 빈 방 30일). 주기적 알람이 아니다. Directory만 1시간 주기 알람이고 하루 24번이다.
- WebSocket Hibernation: acceptWebSocket과 setWebSocketAutoResponse("ping","pong")를 쓴다. setInterval·setTimeout이 없다(grep). ping은 방을 깨우지 않는다. 깨우는 것은 폰이 보내는 ack 프레임뿐이다.
- 반복문 안 질의: ack(최대 100개)가 id마다 DELETE 두 번이다(트랜잭션 한 번 안, 인덱스 있음). store()가 받는 사람마다 INSERT 한 번(받는 사람은 최대 몇 명). 흔한 경로에서 N+1은 위 envelope()뿐이다.
- 커지는 것: 메시지함 deliveries·messages 7일, 노래 3곡·2MB(song_quota), 푸시 작업 30분·3회, rate_limits는 키마다 한 행으로 알람 때 만료분 삭제, 본문은 모두 ack하면 비운다. 상한 없이 커지는 표는 못 찾았다. 단 messages 행(본문 없는 것)은 7일 동안 쌓이며 보낸 사람의 분당 60개 제한이 상한이다.
- 노래 저장: song_blobs 2MB 한 건씩, 업로드 요청에서 readBytes로 한 번 읽는다. 복사는 한 번(buffer를 그대로 바인딩).
- 처리 시간: 위 숫자대로 로컬 순차 요청이 모두 한 자리 ms다.

== 안드로이드 폰: 문제 없음으로 본 것 ==
- 화면이 없을 때: onStop에서 stopConnection이 NetworkCallback 해제, 연결 루프 취소, 소켓 닫기, ping 작업 취소(runSocket finally)를 한다. 폴링·AlarmManager·WorkManager·서비스가 없다. FCM 수신 때만 syncInbox 한 번(onPush)이다.
- 재접속 간격: 1·2·4…60초(backoffMs), 429·4008은 60초. 한 번 시도가 기기 목록·소켓·받은 함 세 요청이다. 너무 짧지는 않다.
- ping은 25초마다, 앞에 있을 때만(2장). pinger는 finally에서 취소한다.
- 녹음기·플레이어: Recorder.stop()에서 release, start 실패에서도 release, 시트의 ON_STOP에서 녹음 멈춤·재생 해제, DisposableEffect에서 정리. 스캐너는 Google 코드 스캐너(별도 화면)라 앱이 카메라를 잡지 않는다.
- 코루틴: 앱 수명 scope(SupervisorJob+Main.immediate)가 하나이고, 장기 작업은 연결 루프(foreground Job을 취소)와 보내기 일꾼 하나뿐이다. 화면 쪽은 rememberCoroutineScope·LaunchedEffect라 수명이 맞는다.
- 저장 크기: feedings를 50개로 자르고(takeLast), 나머지는 pruned가 7일·90일로 자른다.

== iOS 폰: 문제 없음으로 본 것 ==
- 배경: didEnterBackground에서 stopSocket(루프 Task 취소, URLSessionWebSocketTask를 connectOnce의 defer에서 cancel(.goingAway))을 한다. UIBackgroundModes가 project.yml에 없고 백그라운드 작업·타이머·푸시 외 폴링이 없다. NWPathMonitor는 앱 수명 동안 하나이며 돌아올 때만 refresh를 부른다(배경 대기 비용은 낮다).
- URLSessionWebSocketTask: connectOnce의 defer에서 receiver.cancel()과 task.cancel을 한다. 재접속은 1·2·4…60초, 4008과 429는 60초/Retry-After를 따른다.
- AVAudioRecorder·AVAudioPlayer·AVAudioSession: 모든 종료 경로가 AudioSessionRelease.deactivate()(notifyOthers)를 부른다. 시트 onDisappear에서 discard가 타이머·녹음기·플레이어·임시 파일을 정리한다. 10Hz 타이머는 녹음 중에만 돌고 finish·discard에서 invalidate한다. 파형 배열은 60개에서 자른다.
- Task 누수: spawn이 UUID로 추적하고 끝나면 지운다. retryTask·staleRetryTask는 만들 때 이전 것을 취소한다. QRScanner는 dismantle에서 stopScanning한다.
- 저장 크기: feedingLog 30개, processed·shown 7일, reports·alerts 90일로 잘린다(전체를 쓰는 방식은 위 [중간]과 같다).
