# iOS 429 잠금(직접 입력·자동 제출·확인 버튼, Retry-After까지) — 2026-11-05(1105d)
환경: iOS 시뮬레이터 'iPhone Duo'(iOS 27.1)에 main 작업 트리 phone/ios Debug 빌드(xcodebuild, 17:06 설치). 로컬 중계 relay/ `wrangler dev`(8787, 17:06:11 Ready, 이 측정이 띄움).
      차 에뮬레이터 없이 했다(잘못된 코드는 중계만 404로 답한다). 1105b 안드로이드 ④와 같은 방법.
코드: 모두 일부러 넣은 가짜 6자리(000001~000007, 111111~999999, 000000, 121212). 실제 연결 코드·초대 코드는 쓰지 않았다.
입력: 시뮬레이터 화면 키보드(123 → 숫자 키)를 탭. 6자리가 차면 앱이 바로 제출한다(RootView.swift onChange).
중계 한도(contracts-link 9장, relay/src): 설치 id당 10분에 5번 틀림 → 그 창이 끝날 때까지 429, Retry-After = 창 끝까지 남은 초.

## 준비
- 앱은 이전 중계 자격으로 '연결됨'이었다. 설정 → '연결 끊기' → 확인 → 17:07:59.080 DELETE /v1/devices/me 204 → 연결 화면 "연결이 끊겼어요. 다시 연결해 주세요."

## 관찰(버그로 단정하지 않음)
- 확인 버튼이 늦게 켜짐: isPairLocked는 Date()로 계산해 Retry-After가 지나면 바로 거짓이지만, 화면은 lockPair의 `Task.sleep(secs)` 뒤 pairLockedUntil = nil이 될 때 다시 그려진다
  (AppModel.swift:293-301). 이 Task가 약 6%(561초에 36초) 늦게 깼다. 시뮬레이터가 화면 뒤에 있을 때의 타이머 지연(App Nap 등)일 수 있어 실기기에서는 다를 수 있다(미판정).
  그 사이 새 6자리를 치면 submit의 isPairLocked 검사는 통과하므로 자동 제출은 될 것으로 보이나 재지 않았다.
- 잠금 중 'QR 찍기' 버튼은 켜져 있다(RootView.swift:74 `.disabled(connecting)`만). 1105b 안드로이드와 같고 ④ 범위 밖.
- 잠금 중 다시 친 경우 문구에 남은 초가 빠진다(submit이 rateLimited(nil)로 문구를 만듦). 안드로이드와 문구 맞대기는 하지 않았다.
