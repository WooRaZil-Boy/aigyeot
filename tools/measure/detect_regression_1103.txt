아이곁 감지 기기 회귀 (2026-11-03)

목적: 감지 갈래의 앱 코드(kr.aigyeot.app, debug 전용 DetectReplayActivity)가 공식 Pleos 에뮬레이터(AVD PleosProbe, 운전자 user 10)에서 맥 기준값(ref.json)과 11-02 프로브 실측(tools/pleos-probe/device_match_1102.txt)과 같은 울음 확률·경보를 내는지 확인한다.
파일: 시험 PCM 6개(16kHz mono s16le, 10초, 3초 구간 9개씩), 앱 assets의 yamnet.tflite와 cry_head24_rt.json, 맥 기준값 ref.json(소수 둘째 자리 반올림)
방법(S는 mk_pcm이 쓴 데이터 폴더, W는 감지 갈래 작업 폴더):
  adb uninstall dev.probe.pleos                         # 프로브가 있으면 부팅 시험이 마이크를 쓰므로 먼저 지운다
  (cd W && ./gradlew :app:assembleDebug)
  adb install -r W/app/build/outputs/apk/debug/app-debug.apk
  adb shell pm grant --user 10 kr.aigyeot.app android.permission.RECORD_AUDIO
  D=/data/user/10/kr.aigyeot.app/files
  adb shell run-as kr.aigyeot.app --user 10 mkdir -p $D
  for f in S/assets/rt/*.pcm; do adb shell "run-as kr.aigyeot.app --user 10 sh -c 'cat > $D/$(basename $f)'" < $f; done
  adb logcat -c
  adb shell am start -W --user 10 -n kr.aigyeot.app/.detect.DetectReplayActivity
  sleep 20; adb logcat -d -s DETECT:I
읽는 법: 아래 표는 구간 9개의 울음 확률을 기준값(ref)과 기기(dev)로 놓고 절댓값 차이의 최댓값, 경보 일치, 처리 시간(took, 10초 PCM 전체를 최대한 빨리 돌린 시간)을 적었다. 처리 시간의 11-02는 프로브 SoundProbe의 YAMNet 호출 시간이다.
한계: 두 쪽 모두 소수 둘째 자리로 찍히므로 0.01보다 작은 차이는 알 수 없다. 처리 시간은 맥이 다른 작업으로 몹시 바빴던 때(load average 100 이상)에 쟀다.
발견: 작업 폴더의 첫 빌드는 MediaPipeScorer의 setMaxResults(-1)이 기기에서 IllegalArgumentException("If specified, maxResults must be > 0")으로 죽었다(DetectReplayActivity 시작 직후). 이 호출을 뺀 사본으로 아래를 쟀다. 감지 담당이 원본도 같게 고쳤다고 알려 왔다(원본 재측정은 하지 않았다).
