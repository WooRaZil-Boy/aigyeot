# 시뮬레이션과 차량 제어 실측 로그

## `bandit_sim.py`: 아이별 소리 고르기 시뮬레이션

아이마다 방법 3~4개(백색소음, 뱃속 소리, 자장가, 부모 녹음)의 '1분 안 진정' 확률이 다르다고 가정한다. 그 위에서 톰슨 샘플링을 '늘 같은 방법'·'무작위'·'돌아가며'와 비교한다.

- **판정 오류:** 오프라인 평가값(`rt_outcome.py`, Mac)을 넣는다. R3(듣기 틈 + 30초 확인) 판정에서 계속 우는데 그쳤다고 볼 확률 1/180, 그쳤는데 아직 운다고 볼 확률 0/180이다([`rt_outcome.json`](../cry-retrain/rt_outcome.json)).
- **실행:** `python bandit_sim.py 20`(아이당 울음 20번) 또는 `40`. 둘째 인자는 음원 수 K(기본 3). 처음에는 K×2번을 돌아가며 쓴다(3개면 6번, 4개면 8번).
- **11-06 결과(뱃속 소리 추가):** `bandit_1106_K3.txt`(부모 노래 없음, 세 음원)·`bandit_1106_K4.txt`(부모 노래 있음, 네 음원), 울음 40번은 `_T40` 파일. 지표는 위와 같다(마지막 5번의 최선 선택률).
- **최선 선택 비율:** 고른 방법의 확률이 그 아이의 최댓값과 같으면 최선으로 센다(방법이 모두 같은 확률이면 100%).
- **주의:** 결과는 가정한 확률에서 나온 값이다. 실제 아기에서의 효과가 아니다.

## `babycare_Drive.txt`, `babycare_Park.txt`: 아기 케어 차량 제어 실측(2026-11-02)

Pleos 에뮬레이터에서 실측 프로브(`tools/pleos-probe`, `ScenarioProbe --es mode babycare`)로 쟀다.

- **조건:** 주행(기어 D, 60 km/h)과 정차(P). 기어와 속도는 Virtual Console로 정했다. 각 로그 앞부분의 `STATE gear=GEAR_DRIVE speed=16.666668`(m/s, 60 km/h)과 `STATE gear=GEAR_PARK speed=0.0`이 조건이 실제로 걸렸다는 기록이다.
- **방법:** 제어마다 6번 명령을 보내고 다시 읽어 반영을 확인했다. 값은 켜기·끄기(열선 단계 2↔0, 잠금↔해제 등)를 번갈아 보냈고, 첫 목표가 이미 현재 값이면 순서를 한 칸 밀어 첫 명령부터 상태가 바뀌게 했다.
- **판정:** 성공 응답을 받고, 다시 읽은 값도 목표와 같을 때만 `ok`다.
- **로그 형식:** `RES <제어_영역> <회차> ack=<성공 응답 ms> seen=<반영 확인 ms> ok|FAIL`. 성공 응답이 없으면 `noAck`를 붙인다.
- **함께 기록한 것:** 뒷좌석 착석(`GET occupancy ROW_2_*`, 에뮬레이터 기본값은 모두 `true`), 뒷문 리스너 초기값(`EVT door`, 문은 열지 않았다), 주행 시간 API(미지원).
- **재현 방법:** [`tools/pleos-probe/README.md`](../pleos-probe/README.md)의 3장(Virtual Console)과 5장(`babycare`).

| 제어(영역) | 주행 중 | 정차 중 |
| --- | --- | --- |
| 뒷좌석 열선(`ROW_2_LEFT`) | 6/6 | 6/6 |
| 뒷좌석 독서등(`ROW_2_LEFT`) | **0/6**(명령 거절, 오류 50001) | 6/6 |
| 뒷창 잠금(`ROW_2_LEFT`, 뒷좌석 전용 영역) | 6/6 | 6/6 |
| 앞 공조 온도(`ROW_1_LEFT`) | 6/6 | 6/6 |
| 앰비언트 색(전체 영역) | 6/6 | 6/6 |
| 하이패스 안내 음량 | 미지원 | 미지원 |

**11-01 측정과 바뀐 점:** 11-01에 처음 쟀을 때는 측정 코드에 문제가 둘 있어서, 11-02에 코드를 고쳐 다시 쟀다.
- **독서등:** 거절된 명령도 값이 우연히 목표와 같으면 `ok`로 찍혔다.
- **뒷창 잠금:** 앞뒤 전체 묶음 영역이 골라져, 앞창까지 잠갔다.
